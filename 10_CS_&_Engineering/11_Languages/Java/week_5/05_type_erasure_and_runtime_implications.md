# How Generics Work: Type Erasure

- To ensure backwards compatibility with legacy pre-Java 5 bytecode, Java implements Generics via **Type Erasure**.
- **The Process**:
  1. The compiler verifies all generic type safety rules at compile-time.
  2. The compiler **erases** all generic type parameters and replaces them with their bound (e.g., `Object` or the upper bound `Comparable`).
  3. The compiler automatically inserts explicit casts in the generated bytecode.

```java
// Source Code:
List<String> list = new ArrayList<>();
list.add("Hello");
String s = list.get(0);

// Bytecode after Type Erasure:
List list = new ArrayList();
list.add("Hello");
String s = (String) list.get(0);
```

---

# Limitations Imposed by Type Erasure

Because type information does not exist at runtime:

1. **Cannot use primitive types in Generics**: `List<int>` is illegal; must use wrapper `List<Integer>`.
2. **Cannot instantiate generic type parameters**: `new T()` is illegal.
3. **Cannot create generic arrays**: `new T[10]` is illegal.
4. **Cannot check generic types with `instanceof`**: `if (obj instanceof List<String>)` is illegal (only `instanceof List<?>`).
5. **Static fields cannot have generic types**: `private static T data;` is illegal (one static field per class, shared across all type arguments).

---

# Summary

- Java Generics are a compile-time syntactic convenience with zero runtime overhead
- Type parameters are erased and replaced with raw types in compiled bytecode
- Type erasure creates specific restrictions regarding primitives, array creation, and runtime type checks
